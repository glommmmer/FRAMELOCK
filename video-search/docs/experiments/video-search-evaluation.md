# 多视频片段检索样本与评测

日期：2026-11-22。本文定义采集和验收方法；已用用户提供的两条饮料视频准备首批局部开发样本，见 `video-search-m0-beverage.md`。尚无自动检索实测结果，首批样本不构成保留测试集。

## 第一批素材

准备 8 至 12 段可用于测试的短视频，每段约 15 至 60 秒。素材保存在本地，不自动上传。优先自行拍摄，也可使用已确认可用的素材；不要把旧课堂录像自动当作新测试集。

| 内容 | 用途 |
| --- | --- |
| 拿起杯子喝水并放下 | 正例，标注拿起、喝水及完整动作区间 |
| 拿杯子移动，但不喝 | 区分持有物体与动作 |
| 向杯子倒水 | 区分相关但不同动作 |
| 说“我要喝水”但不喝 | 检验模型是否被语音误导 |
| 无声喝水 | 检验是否只依赖转写 |
| 在较长片段末尾快速喝一口 | 检验采样漏检与边界 |
| 同一个视频喝两次 | 检验重复事件能否找全 |
| 空场景或完全无关内容 | 负例 |

改变杯子、机位、背景或拍摄者，避免只记住某个杯子的外观。按源视频和拍摄会话分割开发集、保留测试集，不能把同一录像切成相邻片段后分到两边。初期开发约占三分之二，其余保留；小样本结果仅用于决定是否继续开发。

## 标注格式

媒体清单至少包含：`videoId`、本地路径、文件哈希、时长、数据划分、内容类别。

每条查询至少包含：`queryId`、查询原文、检索范围、数据划分、所有正确事件的 `videoId/startMs/endMs`、允许的动作定义、容易混淆的反例说明。没有答案时正确事件数组为空。

时间区间采用整数毫秒和 `[startMs, endMs)`。先写清“拿杯子喝水”是否要求包含拿起与放下；动作定义不能在看到模型答案后更改。

候选结果保存：`queryId`、运行配置版本、视频与解析版本、起止时间、排序、核验结果、证据、耗时、工具调用量、Token 和估算费用。不保存凭空填写的成功结果。

## 对照实验

| 路径 | 方法 | 回答的问题 |
| --- | --- | --- |
| A | 只用语音和 OCR 检索 | 文字信号能覆盖多少需求 |
| B | 加入连续画面描述、融合检索和固定核验 | 视觉解析增加了什么 |
| C | 在 B 基础上允许 Agent 补查和调整时间范围 | 自适应工具调用是否值得其成本 |

三条路径使用同一批视频和查询。C 的所有补查消耗计入延迟与费用，不能只计最后一次调用。保留测试集只在关键版本验收时运行，不反复据其调提示词。

## 指标定义

- 事件命中：来源视频相同，预测区间与标注区间的交并比 tIoU 达到 0.5。一个结果与一个真实事件最多匹配一次，按排序一对一匹配，防止重复片段虚增召回。
- Recall@5：每条有答案查询的前五个结果覆盖的真实事件数 / 真实事件总数，再计算查询平均；同时报告事件总量和分子分母。
- Precision@5：前五个返回结果中正确事件数 / 实际返回数；有答案却返回零个结果记 0。无答案查询单列，不混进该指标。
- 无答案误报率：无答案查询中返回至少一个“已确认命中”的查询数 / 无答案查询数。待核实候选与已确认结果分开报告。
- 边界误差：对匹配成功事件分别报告开始和结束的绝对误差中位数；漏检数必须同时报告，不能只展示成功事件的边界。
- 工程指标：解析每分钟源视频的耗时与费用；查询端到端耗时、工具调用数和消耗。样本足够时报告 P50/P95，小样本先展示每次原始值和范围。

M0 暂定进入下一阶段的门槛：开发集至少 12 条查询，其中至少 4 条无答案；B 的 Recall@5 达到 0.8，且无答案误报不超过 1 条。另提供可回看的正例和干扰例。该门槛是工程推进标准，不是已实现效果或行业标准；保留集仍单独报告，不为通过门槛修改标注。

M3 扩展到至少 30 条查询，增加游戏素材和多事件查询。是否保留 Agent 额外步骤，依据 C 相对 B 的召回、误报、费用和延迟共同决定；不预设提升百分比。

## 故障验收

使用模拟接口验证模型超时、429、错误 JSON 和工具返回为空；使用实际中间件验证消息重复、Worker 终止、Redis 丢失、Qdrant 不可用、Outbox 补发和删除清理失败。供应商真实调用只做小规模验证，不能用模拟结果宣称真实模型吞吐量。

记录每个案例的输入条件、预期业务状态、最终状态、恢复步骤和日志位置。日志不含密钥、完整签名地址和不必要的用户内容。
